# LucidHover — Hover Card UI Redesign Spec

**Audience:** coding agent implementing the changes
**Reference implementation:** `lucidhover-card-redesign.html` (companion file — treat it as the canonical markup/CSS; this document is the source of truth for *what* and *why*)
**Scope:** the explanation card webview only. No changes to LLM prompting, caching, or JSON schema except where noted.

---

## 1. Context

LucidHover renders a strict-JSON LLM explanation into a deterministic webview card. **This card is the expanded view** — the user reaches it by clicking "show more" in the hover tooltip, so the full explanation is expected here. Truncation/clamping is the hover tooltip's responsibility, not this card's.

The current card works but has hierarchy, visibility, and state-handling problems (Section 3). This redesign restructures the card using **only** VS Code's own UI primitives:

- Theme tokens (`--vscode-*` CSS variables) for all colors and fonts — the card must adapt to every theme, including high contrast, with zero per-theme CSS.
- Codicons (`@vscode/codicons`) for all icons — the same icon font the workbench uses.
- No external UI libraries, frameworks, icon sets, or webfonts.

## 2. Constraints (hard requirements)

1. No external libraries or frameworks. Vanilla HTML/CSS in the webview.
2. Every color must come from a `--vscode-*` token, each with a sensible fallback, e.g. `var(--vscode-editorHoverWidget-border, var(--vscode-editorWidget-border))`.
3. Every icon must be a codicon.
4. All interactive elements must be keyboard-focusable with a visible `:focus-visible` outline using `--vscode-focusBorder`.
5. Respect `prefers-reduced-motion` for all animation.
6. Buttons must remain visible and readable even if the codicon font fails to load (icon + text label, never icon-only).
7. Render the explanation in full — no clamping, truncation, or "More…" toggle in this view (the user already expanded from the hover).

## 3. Problems with the current card

| # | Problem | Severity |
|---|---------|----------|
| P1 | Header leads with "LucidHover: Explanation" branding instead of the symbol identity | High |
| P2 | Four actions at one level: navigation links ("See full blast radius", "Trace execution") mixed with utilities ("Regenerate", "Copy") | High |
| P3 | "USED BY" shows one caller while the prose mentions three; no count, no list | High |
| P4 | Explanation paragraph is a wall of text with no measure limit | Medium |
| P5 | "SIDE EFFECTS" can contradict the prose ("no side effects" vs. a listed bullet) — no empty state | Medium |
| P6 | Disclaimer renders at the same visual weight as content | Low |
| P7 | No stale indicator when the cache entry predates the file's last change | Low |

## 4. Target structure

```
┌──────────────────────────────────────────────────────┐
│ ⓜ formatDate                  [⟳ Regenerate] [⧉ Copy] │
│   Function · repomap/utils.js · 2 min ago            │
├──────────────────────────────────────────────────────┤
│ WHY IT EXISTS                                        │
│ Full explanation text, rendered in full…             │
├──────────────────────────────────────────────────────┤
│ USED BY (4)                                          │
│ ⓜ sendWelcomeEmail                 repomap/email.js  │
│ ⓜ renderDashboard                  ui/dashboard.js   │
│ ⓜ exportUsersReport                reports/export.js │
│ See full blast radius ›                              │
│ Trace execution from here ›                          │
├──────────────────────────────────────────────────────┤
│ SIDE EFFECTS                                         │
│ ✓ None detected — pure function                      │
├──────────────────────────────────────────────────────┤
│ ⚠ Generated by a local LLM — may be inaccurate…      │
└──────────────────────────────────────────────────────┘
```

Five zones: **header**, **why**, **used by**, **side effects**, **footer**. Sections separated by `1px solid var(--vscode-widget-border, rgba(128,128,128,0.2))`.

## 5. Zone specifications

### 5.1 Header

- Symbol-kind codicon (e.g. `codicon-symbol-method`) tinted with `--vscode-symbolIcon-methodForeground` (fall back to `--vscode-symbolIcon-functionForeground`).
- Symbol name in an inline-code chip: `--vscode-editor-font-family`, 600 weight, `background: var(--vscode-textCodeBlock-background)`, `border-radius: 4px`, ellipsis on overflow.
- Meta row (11px, `--vscode-descriptionForeground`): `{kind} · {relative file path} · {relative time}`. File path in `--vscode-textLink-foreground`. Relative time ("2 min ago") with the absolute timestamp in the `title` tooltip.
- **Actions: `Regenerate` and `Copy` as labeled secondary buttons**, top-right. This replaces the old inline text links.

```css
.lh-btn {
  appearance: none;
  border: none;
  display: inline-flex;
  align-items: center;
  gap: 5px;
  padding: 3px 10px;
  border-radius: 4px;
  cursor: pointer;
  font-family: var(--vscode-font-family);
  font-size: calc(var(--vscode-font-size) - 1px);
  line-height: 18px;
  color: var(--vscode-button-secondaryForeground);
  background: var(--vscode-button-secondaryBackground);
}
.lh-btn:hover { background: var(--vscode-button-secondaryHoverBackground); }
.lh-btn:focus-visible { outline: 1px solid var(--vscode-focusBorder); outline-offset: 1px; }
```

```html
<div class="lh-actions">
  <button class="lh-btn" data-command="regenerate" title="Regenerate explanation">
    <span class="codicon codicon-sync" aria-hidden="true"></span>Regenerate
  </button>
  <button class="lh-btn" data-command="copy" title="Copy explanation as Markdown">
    <span class="codicon codicon-copy" aria-hidden="true"></span>Copy
  </button>
</div>
```

- Busy state: while regenerating, add `.is-busy` (opacity 0.7, `codicon-sync` spins via keyframes, animation disabled under `prefers-reduced-motion`) and set `disabled`.

### 5.2 Why it exists

- Section title style (shared by all sections): 11px, 700 weight, uppercase, `letter-spacing: 0.04em`, color `--vscode-sideBarSectionHeader-foreground` (fallback `--vscode-descriptionForeground`).
- Body: render the **full** explanation text — this card is the expanded view, so no clamping or "More…" toggle. Readability comes from `max-width: 60ch` and `line-height: 1.5`.
- Inline code spans use `--vscode-textCodeBlock-background` chips.

### 5.3 Used by

- Title includes a count badge: `background: var(--vscode-badge-background)`, `color: var(--vscode-badge-foreground)`, `border-radius: 8px`, 10px/16px.
- Render up to 3 callers as rows: kind codicon + caller name + right-aligned file path (11px, descriptionForeground). Rows are full-bleed with `margin: 0 -6px`, `border-radius: 4px`, hover `background: var(--vscode-list-hoverBackground)` — Explorer-style.
- Each row carries `data-command="reveal"` and `data-target="{file}:{symbol}"`.
- Below the list, the two navigation links ("See full blast radius", "Trace execution from here") with trailing `codicon-chevron-right`; chevron translates 2px on hover (disabled under reduced motion). These are the *only* actions in this section — utilities live in the header.

### 5.4 Side effects

Render exactly one of two states, driven by the JSON array — never both:

- **Empty** (`sideEffects: []`): `codicon-check` tinted `--vscode-testing-iconPassed` (fallback `--vscode-charts-green`) + "None detected — pure function" in descriptionForeground.
- **Present**: list with `codicon-warning` tinted `--vscode-problemsWarningIcon-foreground` (fallback `--vscode-editorWarning-foreground`).

This fixes P5: the renderer, not the model prose, owns the claim.

### 5.5 Footer

- `codicon-warning` + "Generated by a local LLM — may be inaccurate, verify before relying on it." at 11px, `--vscode-descriptionForeground`, separated by the standard section border.
- **Stale state** (P7): if `generatedAt` predates the file's content hash/mtime, add `.is-stale` → text in `--vscode-editorWarning-foreground`. Suggested copy: "Generated before the latest changes — consider regenerating."

## 6. State matrix

| State | Trigger | Visual change |
|-------|---------|---------------|
| Default | — | As wireframe |
| Regenerating | `regenerate` command sent | `.is-busy` on button, spin icon, disable both buttons |
| No side effects | `sideEffects` empty | Check-icon empty state |
| Has side effects | `sideEffects` non-empty | Warning-icon list |
| Stale cache | `generatedAt` < file mtime/hash | `.is-stale` footer |
| Codicon font missing | CSS load failure | All buttons/rows still readable (labels are real text) |

| Token | Used for |
|-------|----------|

| `--vscode-font-family` / `-size` / `-weight` | Base type |
| `--vscode-editor-font-family` | Symbol name, inline code |
| `--vscode-descriptionForeground` | Meta row, empty states, footer |
| `--vscode-textLink-foreground` / `-activeForeground` | Nav links, file path |
| `--vscode-textCodeBlock-background` | Code chips |
| `--vscode-button-secondaryBackground` / `-Foreground` / `-HoverBackground` | Regenerate / Copy |
| `--vscode-sideBarSectionHeader-foreground` | Section titles |
| `--vscode-badge-background` / `-foreground` | Used-by count |
| `--vscode-list-hoverBackground` | Reference row hover |

## 8. Codicon reference

`symbol-method` (kind), `sync` (regenerate), `copy` (copy), `chevron-right` (navigation), `check` (pure), `warning` (side effects, footer).

## 9. Webview wiring

1. Load codicons from the extension install and allow them in CSP:

```ts
const codiconUri = webview.asWebviewUri(
  vscode.Uri.joinPath(extensionUri, 'node_modules', '@vscode/codicons', 'dist', 'codicon.css')
);
// CSP meta must include:
//   style-src ${webview.cspSource} 'unsafe-inline';
//   font-src ${webview.cspSource};
```

2. Command protocol — buttons/links carry `data-command` attributes; one delegated click listener posts to the extension:

| `data-command` | Payload | Extension behavior |
|----------------|---------|--------------------|
| `regenerate` | symbol id | Invalidate cache entry, re-run local LLM, re-render card |
| `copy` | symbol id | Write Markdown rendering of the JSON to clipboard |
| `reveal` | `{file, symbol}` | Open file at symbol location |
| `blastRadius` | symbol id | Expand full caller graph view |
| `trace` | symbol id | Start execution trace from this symbol |

3. Keep the renderer deterministic: JSON in → HTML string out. No model-generated HTML.

## 10. Accessibility

- Card root: `role="document"`, `aria-label="Explanation of {symbol}"`.
- All decorative icons: `aria-hidden="true"`.
- All buttons: real `<button>` with `title`; all rows/links focusable.
- `:focus-visible` outline: `1px solid var(--vscode-focusBorder)`.
- All motion guarded by `@media (prefers-reduced-motion: reduce)`.

## 11. Acceptance criteria

- [ ] Card header shows kind icon, symbol name chip, and meta row (kind · file · relative time with absolute-time tooltip)
- [ ] Regenerate and Copy render as labeled secondary buttons in the header and work when codicons fail to load
- [ ] Regenerate shows spinning busy state and disables during regeneration
- [ ] "Why" text renders in full — no clamp, no "More…" toggle (this card is the expanded view); stays readable via the 60ch measure and 1.5 line-height
- [ ] Used-by shows count badge + up to 3 caller rows with file paths and list-hover styling
- [ ] Blast radius and trace are chevron navigation links inside Used-by, not mixed with utilities
- [ ] Side effects renders exactly one state (empty check / warning list) from the JSON array
- [ ] Footer disclaimer is 11px descriptionForeground with warning icon; stale state switches to warning color
- [ ] No hardcoded colors — everything resolves to `--vscode-*` tokens with fallbacks
- [ ] Verified in at least one dark, one light, and one high-contrast theme
- [ ] Keyboard: every interactive element reachable and visibly focused

## 12. Reference implementation

`lucidhover-card-redesign.html` contains the complete markup and CSS implementing everything above, with `{{CODICON_URI}}` and `{{...}}` placeholders marking where the extension injects runtime values. Prefer copying its CSS verbatim over re-deriving it.
