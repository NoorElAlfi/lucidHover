## Decisions made
- **"Used by" rows drop the per-caller file path** the doc's mockup shows. `used_by` is bare LLM-derived names with no file info, and resolving one would mean an RPC call from the panel's render path, which Core Rule 4 forbids. User confirmed via `AskUserQuestion`.
- **Reused the existing `dirty`/`stale`/`fresh` freshness machinery** (`DirtyTracker`/`StaleTracker`, already built for hover in session 13) for the footer's stale indicator, instead of the doc's own naive "generatedAt < file mtime" check — the panel simply hadn't read that state before. Duplicated `freshnessOf`/`FreshnessState` locally rather than importing from `functionHoverProvider.ts` (which already imports this file, so importing back would be circular).
- **Kept `calls` and `risk_note`** as extra sections beyond the doc's literal 5-zone target — real existing fields, not something any of the doc's P1-P7 problems asked to remove.
- **Dropped the Function-vs-Method label distinction** (`code-reviewer` finding): the dotted-qualified-name heuristic mislabels a nested closure (a named function declared inside another function) as "Method," since `flattenWithQualifiedNames` qualifies by every enclosing *symbol*, not just class ancestors, and VS Code's JS/TS `DocumentSymbolProvider` genuinely nests such symbols. Always shows "Function" now; real `SymbolKind` plumbing would be needed to restore the distinction correctly, and it's unavailable for `showRow`'s hover-push path regardless.
- **"Back to caller" is a single slot, not a history stack** (one hop back), scoped this session at the user's request after live testing surfaced the same-file `Alt+Left`-doesn't-help gap. Matches on bare name + a 15s recency window (`BACK_TARGET_TTL_MS`) rather than exact identity, since the navigate command that resolves the actual destination is a separate, fire-and-forget VS Code command with no result channel back to the panel — see the code's own doc comments for the full tradeoff.
- **Blast radius / execution trace UI redesign deferred to a follow-up session**, per explicit user instruction after live testing — this session's scope stayed the single-explanation view only, matching how the task was originally framed.

## Deviations from spec
- `.lh-card` has no `max-width: 460px` cap (the reference HTML's value, sized for a hover-tooltip-shaped card) — this is the always-visible docked panel, so it fills whatever width the sidebar gives it. `.lh-body`'s `max-width: 60ch` (paragraph readability) is kept.
- Footer extends the doc's P7 "stale" state to also cover "dirty" (an unsaved in-memory edit), which the doc doesn't name but which the reused freshness machinery already distinguishes.
- Two features present in the redesign are not in the design doc at all: the "Back to caller" affordance and the failed-regenerate busy-state recovery — both were real bugs/gaps found via live manual testing, not doc requirements.
