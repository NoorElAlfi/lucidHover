## Decisions made
- **User chose option (a) via `AskUserQuestion`**, per the session brief's explicit requirement not to guess a shape-changing UI/RPC decision: keep the linear timeline as the default view, add an inline "+N other calls from here" expander at any hop, rather than replacing the view with a full tree (b) or adding a second independent trigger/RPC (c). This kept the change additive to the existing `get_call_trace`/`renderTrace` rather than introducing a second graph-walk method or a second command.
- **Branch alternates are never themselves walked** -- a deliberate v1 scope cut matching the AskUserQuestion answer ("one hop of alternates, not a second recursive tree"). No `visited`-set interaction, no recursion; each hop's branch computation is independent and one-shot.
- **Reused `RepoMap._cap`/`CALLER_CALLEE_CAP` directly, not a new constant**, per the session brief's explicit instruction to reuse session 47's pattern rather than invent a new number. Measured first against real pokerogue (6,633 functions, same repo session 47 used) before committing to this: 246 functions have more than 15 confident callees at a single hop (e.g. `initMoves` in `src/data/moves/move.ts`, 248) -- a real, observed fan-out problem, confirming the cap is warranted and that reusing the existing value (rather than a smaller or larger one) is reasonable, since users are already used to that convention from `get_function_context`/`get_blast_radius`.
- **A branch point's `depth` matches its corresponding primary-path node's depth**, not the depth of the caller that produced it -- this lets the panel attach "+N other calls from here" to the node it renders right after, via a simple `find(b => b.depth === node.depth)` lookup, the same shape session 47's `omissions.find(o => o.depth === depth)` already established.
- **No branch point is recorded for a cycle-closing terminal hop** -- the append happens only after a primary-path node is successfully added, so a hop that breaks early (`primary in visited`) never produces an orphaned branch point with no matching node to attach to. Documented and tested (`test_get_call_trace_no_branch_recorded_for_cycle_closing_hop`).
- **`enrichOne` extracted as a shared helper within `callTraceCommand.ts`** (not shared across files with `blastRadiusCommand.ts`) -- consistent with session 46's own established precedent that near-duplicate enrichment logic between the two *files* stays duplicated (two call sites don't yet justify a cross-file abstraction), while sharing *within* one file to avoid enriching the same shape of data two different ways was a reasonable, smaller-scoped call.
- **`<details>/<summary>` for the expand/collapse UI**, not a custom toggle with a click listener -- native, needs no JS beyond what the existing nonce'd `<script>` block already provides, and works cleanly under the panel's strict CSP (`script-src 'nonce-{nonce}'`) with zero new inline-handler risk.
